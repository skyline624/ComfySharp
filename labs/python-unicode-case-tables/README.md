# CPython full upper/title tables

This directory statically extracts the additional mappings needed by the four exact `CaseConverter` modes. It does not execute CPython casing, generate a source oracle or ship a Python runtime. The existing [lower table and extractor](../python-unicode-tables/README.md) remain unchanged.

The source is CPython **3.12.10**, Unicode **15.0.0**, annotated tag object `f86fdcac4c104bb671f86eb77cf98a6aa764c04e` resolving to commit [`0cc81280367df838c4b199f8f0378837165071c2`](https://github.com/python/cpython/tree/0cc81280367df838c4b199f8f0378837165071c2). [provenance.json](provenance.json) preserves the same six raw source/license identities and tag-resolution endpoints as the lower foundation. The original downloaded files are not distributed here. No signature verification beyond the already documented tag-object resolution is claimed.

## Static derivation

`extract.py` verifies its pinned provenance and every source's byte length/SHA-256 before reading the C data. Its parser accepts only the expected decimal integer arrays and six-field C records, verifies SHIFT=7, EXTENDED_CASE_MASK=0x4000 and all index dimensions/bounds. No `eval`, upstream import or builtin casing is used.

The lookup is `index1[cp >> 7]`, then `index2[(index << 7) + (cp & 127)]`. The C record fields are upper, lower, title, decimal, digit, flags. Only **upper** and **title** are extracted. If the extended bit is present, each field's low 16 bits identify the extended-array offset and its high byte is the sequence length. Otherwise the field is a signed scalar delta. Each generated mapping contains one to three valid scalars, identities are omitted and keys retain ascending scalar order. Surrogates are excluded. The source code, provenance and six raw files are rehashed after extraction and before publication of generated bytes.

The resulting compact UTF-8 LF JSON is `src/ComfySharp.Nodes/Resources/PythonUnicode/upper-title-3.12.10.json`: **44,021 bytes**, SHA-256 `64b2f8c52989663aa8ff7e8d72afa31cdf813fbd80714ed12ab840222ee0ebe7`.

The separate prospective `CaseConverter` source laboratory provides that independent comparison after publication and collection.

Given the six exact originals in a separate local directory, run this optional developer tool using only Python's standard library:

```powershell
python -I -S -B labs/python-unicode-case-tables/extract.py --source-directory <original-directory> --check src/ComfySharp.Nodes/Resources/PythonUnicode/upper-title-3.12.10.json
```

`--output <new-file>` creates an absent file exclusively and refuses a destination inside the original source directory. The extractor never downloads files. It is not a product, .NET test or application dependency.

## C# adaptation

`PythonUnicodeCase.Upper`, `.Capitalize`, `.Title` and `.Lower` accept valid Unicode scalar strings and a cancellation token. Lower delegates to the existing helper. Upper uses full upper mappings without context. The new resource is embedded with an exact logical name; the loader checks byte length and SHA before parsing, then validates provenance, counts, sorted unique scalar keys and expansion shapes before publishing immutable dictionaries. The lower resource SHA remains `6381d72114b8aa4ee5c0dd04fcbb55395964ab1ca92832e7784f887dfbf8b42c`.

Capitalize and Title reuse the lower helper's traversal and its existing Cased/Case_Ignorable properties. They do not lowercase independent substrings or transformed output. Capitalize titlecases the first original scalar, even when it is not a letter, and contextually lowercases the remainder. Title chooses full title when the immediately preceding original scalar is not Cased, and lower otherwise. It updates this state after every original scalar, including combining marks and punctuation. This is Python's algorithm, not word segmentation or .NET `TextInfo` behavior.

Final_Sigma uses a different state: it skips Case_Ignorable before checking Cased. In particular U+0345 has both properties: Title's preceding state sees Cased, while Final_Sigma skips it. A backwards pass records the following relevant context only at sigma offsets, and a forwards pass emits the result while preserving both preceding states. This is linear in the input and output size and does not repeatedly scan long combining runs.

No NFC, trimming, casefold, swapcase, locale-dependent casing or OS Unicode tables are added. Isolated UTF-16 surrogates produce the existing `unsupported_unicode_value` diagnostic with their UTF-16 offset; empty strings and NUL remain valid. Cancellation is checked before reads, through decoding/context/output passes and before return. Immutable resource initialization, bounded allocations and a single string allocation are not interrupted in the middle. Output-length arithmetic is checked against the .NET string bound; there is no additional arbitrary text quota or truncation.

The managed helper tests contain explicit examples and structural/provenance negative controls. Those expected examples are ordinary test assertions, not captured CPython output. They exercise full expansions, title versus upper, original first-scalar sigma context, U+0345 versus a non-Cased combining mark, astral/NUL, cultures, cancellation, invalid UTF-16 constructed inside test bodies, concurrent immutable reads and long ignorable sequences. Independent source fixtures remain separate and immutable.
