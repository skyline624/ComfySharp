## What the traces establish

`COMFYSHARP_CLIP_TRACE_DIR` enables an additional observation before the unchanged stock assertions. Actual encoder forwards provide all post-block states, final states and pooled outputs. Embeddings, first LayerNorm and Q/K/V are separately reconstructed from the same borrowed weight bank; they are not hooks inside the forward. Trace capture does not change the acceptance corpus, tolerance or three assertion forwards. It adds a warmup and allocations, so memory/timing samples cannot be compared directly with a trace-disabled run.

All recorded parameter hashes and shapes agree: 197 L tensors and 517 G tensors. Configurations, tokens and token counts also agree. An offline comparison verified 654 payloads against their declared SHA-256, dimensions and byte counts across source traces, local Windows captures and the three CI captures. Parameter payloads themselves are not included; their hashes are generated by the capture process and compared, rather than independently rehashed from artifacts.

Embeddings are bit-identical on every system. First LayerNorm differs on Linux/macOS, still within the existing bound at that boundary:

## Source and native controls

The official PyTorch 2.10 and 2.13 `layer_norm_kernel.cpp` files are byte-identical (SHA-256 `14c765e7e931ea313bf0ef42b0c9099d7e762c8f3d33ee408e96807435756711`); so are their `moments_utils.h` files (`ddc188f6752d2b7c04f443a476461d507f041ab6a2a141aa459a8cfa10ce3170`). Rowwise moments use vector reductions whose grouping depends on vector width. Identical source does not establish identical compiled dispatch or arithmetic. [LayerNorm 2.10](https://github.com/pytorch/pytorch/blob/449b1768410104d3ed79d3bcfe4ba1d65c7f22c0/aten/src/ATen/native/cpu/layer_norm_kernel.cpp), [LayerNorm 2.13](https://github.com/pytorch/pytorch/blob/cf30153c4c131c8164ee7798e5022d810682e2cb/aten/src/ATen/native/cpu/layer_norm_kernel.cpp), [moments 2.10](https://github.com/pytorch/pytorch/blob/449b1768410104d3ed79d3bcfe4ba1d65c7f22c0/aten/src/ATen/native/cpu/moments_utils.h).

An independent Windows source experiment changed only ATen dispatch from AVX2 to DEFAULT in fresh laboratory processes, retaining PyTorch 2.13, source, parameters, dtype and thread count. AVX2 reproduces the original first LayerNorm exactly. DEFAULT differs by at most 4.76837158203125e-7 for both widths; three repetitions are identical within each process. This demonstrates dispatch sensitivity in source computation without involving the C# port.

A subsequent full L source experiment under DEFAULT retained the stock corpus, all 197 parameter hashes and the original options. Its three forwards were identical. Relative to the original AVX2 source, the final tensor has 1,363 elements outside the unchanged bound (maximum absolute difference 0.00022834539413452148); the selected intermediate tensor has 15,089 outside it (maximum 0.0012073516845703125). Raw and projected pooling remain within the bound in that experiment. The stock corpus SHA was checked before and after; no fixture was rewritten.

This source-versus-source failure shows that the current Windows AVX2 reference also tests portability of native arithmetic. It does not by itself explain the Linux/macOS results, waive their failures, or establish a new accepted profile. PyTorch documents the distinction between mathematical equivalence, repeatability and equality across platforms; it supplies no CLIP-specific numerical bound. [PyTorch numerical accuracy](https://docs.pytorch.org/docs/2.10/notes/numerical_accuracy.html).

## Remaining qualification work

The next comparisons must distinguish source fidelity on a target backend from portability to the original Windows reference: identical saved inputs for isolated operators, precise native build/dispatch evidence, and independent frozen-source execution in matched environments where necessary. A higher-precision calculation can diagnose individual operations but cannot replace the frozen-source oracle.

No new profile or acceptance threshold has been adopted. Any future backend-specific qualification requires a documented protocol fixed before acceptance, independent source evidence and held-out cases; fitting a threshold to these failing product outputs is insufficient. Original failures remain recorded. Pretrained checkpoints, downstream generation, GPU execution, training, complete model families and V1 remain unqualified.
